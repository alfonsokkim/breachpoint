# A2: Camera and spatial queries

This records the original A2 foundation. For the current map connection and
collision behaviour, see [CameraWorld.md](CameraWorld.md).

This block builds on A1. It adds a first-person camera and the shared box-query
API for later shooting and enemy line-of-sight checks. The scene is still the
starter tetrahedron, not the voxel level.

## Try it

From the group project directory:

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/Craft
```

1. Press Enter, then Tab to capture the mouse.
2. Use WASD to move. Move the mouse to look around.
3. Check that the position changes while eye height stays at 1.6. Diagonal
   movement should not be faster than moving straight.
4. Aim at the tetrahedron. The centre crosshair is the camera ray. The panel
   reports a bounding-box hit distance, which can include empty space beside
   the sloping faces. Looking away should report no hit.
5. Press Tab to release the mouse and use the panel. Switching focus away
   releases it too. Press Tab after returning to capture it again.
6. Run the benchmark. The camera resets and stays still until completion.
   The course timer still measures only scene rendering, not ImGui or swap.

Esc quits. Benchmark runs remain labelled `starter-3d-tetrahedron` and do not
measure the planned voxel game. The benchmark requires a 1920 x 1080 framebuffer.

## Camera contract

World Y is up. The initial eye position is `(0, 1.6, 4)`, facing negative Z with
a 20-degree downward tilt so the starter object is visible. Positive yaw turns
right and positive pitch looks up. Pitch is limited to `[-89, 89]` degrees.

`move({right, forward}, deltaSeconds)` walks at four world units per second on
the horizontal plane, regardless of pitch. Diagonal input is normalised. The
app limits each frame's movement delta to 0.1 seconds to avoid a large jump
after a stall. `setPosition(...)` lets Jason's later collision code apply a
corrected position. There is no gravity, jumping or collision in this block.

`ray()` returns `{position, forward}` with unit-length direction, so its `t`
is distance in world units. `viewProjection(aspect)` uses a 55-degree vertical
field of view and near/far planes of 0.1 and 100.

## Shared query contract

Both queries accept a caller-owned `std::vector<Aabb>` of world-space boxes.
They scan the boxes using A1's slab intersection. They do not own voxel data,
build meshes, or decide which blocks are solid.

```cpp
const auto hit = craft::core::nearestBoxHit(camera.ray(), targetBoxes, 30.0F);
if (hit) {
  const auto targetIndex = hit->index;
  const auto distance = hit->t;
}

const bool clear = craft::core::hasLineOfSight(enemyEye, playerEye, solidBoxes);
```

`nearestBoxHit` returns the box's index in the supplied vector and the smallest
nonnegative ray parameter within the inclusive limit. Equal returned parameters
keep the first box. For non-unit directions, `t` is a parameter, not distance.
A miss, invalid ray or invalid limit returns no hit. Invalid boxes are ignored,
matching A1, so callers should supply valid bounds.

`hasLineOfSight` checks the finite segment from one endpoint to the other.
Boxes behind the source or beyond the destination do not block it. Touching a
box, including at either endpoint, counts as blocked. A zero-length segment
checks whether the point overlaps any box. Nonfinite endpoints return false.
Pass only world occluders, not the enemy/player's own hitboxes. At a surface,
place the eye outside the solid box rather than ignoring a genuine wall hit.

For player shooting, compare target and world hit distances before applying a
hit. For counterfire, use the bounded world sight query before advancing the
exposure timer. Neither gameplay system is implemented here.

## Integration boundary

Jason can expose or cache world-space boxes for solid voxels without changing
the world storage design. Avoid rebuilding that vector every frame. The initial
query is a linear scan. A grid traversal can replace it later if profiling
shows it is needed. The example diagnostics' four faces, four triangles and
one draw call describe only the tetrahedron scene, excluding UI.

The next step is connecting these queries and camera position correction to
Jason's world API. Weapon models, shooting, target parts, enemy damage and
muzzle flashes remain later blocks.
