## The ray and box

A ray has an origin and a direction. Points along it are calculated as:

```text
point(t) = origin + t * direction
```

An axis-aligned bounding box (AABB) has minimum and maximum coordinates on
each axis. Its faces stay parallel to the world axes.

`intersectRayAabb` returns an optional ray parameter `t`. An empty result means
no intersection within the requested range. The direction is not normalised
inside the function. With a unit direction, `t` is distance in world units.
Otherwise, it is a parameter scaled by the length of the direction.

The accepted range is `[0, maxT]`, including both endpoints. The default maximum
is the largest finite float. An origin inside or on the box returns zero, since
the ray already overlaps the box. Touching a face, edge, or corner counts as a
hit. A zero direction, non-finite input, negative limit, or reversed bounds
returns no hit.

## Worked example

Take a box from `(1, 1, 1)` to `(2, 2, 2)` and a ray with origin
`(0, 1.5, 1.5)` and direction `(1, 0, 0)`.

| Axis | When the ray is inside that axis's bounds                         |
| ---- | ----------------------------------------------------------------- |
| X    | From `t = 1` to `t = 2`.                                          |
| Y    | Always, because `1.5` is in `[1, 2]` and the Y direction is zero. |
| Z    | Always, for the same reason.                                      |

All three intervals overlap starting at `t = 1`. The hit position is
`(0, 1.5, 1.5) + 1 * (1, 0, 0) = (1, 1.5, 1.5)`.

With direction `(2, 0, 0)`, the same position is reached at `t = 0.5`.
With `maxT = 0.99` and the original unit direction, the result is no hit.

For a ray going in the negative direction, the two plane intersections are
swapped so that the smaller parameter is always the entry point. For a zero
direction component, the ray must already lie within that axis's bounds.

The implementation keeps the latest entry and earliest exit across the three
axes. If entry exceeds exit, there is no common interval and therefore no hit.
Intermediate calculations use `double` to avoid overflow when dividing by a
very small nonzero float direction.

## Questions to be able to answer

1. Why must the X, Y, and Z intervals overlap?
2. Why does a parallel ray outside one axis's bounds miss the entire box?
3. Why does changing direction from `(1, 0, 0)` to `(2, 0, 0)` halve `t`?
4. Why does a ray starting inside the box return zero?
5. How could a future shooting query compare this result with the wall-hit
   parameter to prevent shots passing through walls?

The future query must compare parameters from the same ray. The voxel world
and target list are added in later blocks.
